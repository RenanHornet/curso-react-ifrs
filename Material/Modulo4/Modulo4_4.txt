=== Boas práticas para exibição de dados e tratamento de erros ===
Ao desenvolver interfaces que lidam com dados dinâmicos, é importante seguir algumas boas práticas para garantir uma experiência de usuário fluida e agradável.

=-=-= Usar indicadores de carregamento =-=-=
Procure manter o usuário informado sobre o progresso enquanto os dados estão sendo carrregados é essencial. Indicadores como "Carregando..." ajudam a evitar que o usuário pense que a aplicação travou. use um spinner ou barra de progresso visual quando for necessário bsucar grandes quantidades de dados. 

Veja um exemplo abaixo:

{loading && <div className="spinner">Carregando...</div>}

=-=-= Exibição condicional de erros =-=-=
Quando ocorre um erro, mostre uma mensagem de erro clara e, se possível, uma sugestão para o que o usuário pode fazer para resolver o problema.

Veja um exemplo abaixo:

{erro && <p className="error">Ocorreu um problema ao carregar os dados. Por favor, tente novamente mais tarde.</p>}

=-=-= Tratamento de requisições lentas =-=-=
Quando ocorre um erro, mostre uma mensagem de erro clara e, se possível, uma sugestão para o que o usuário pode fazer para resolver o problema. Veja um exemplo abaixo:

const fetchUsuarios = async () => {
    try {
        // Cria uma instância do Axios com um tempo limite de 5 segundos
        const response = await axios.get(
          "https://jsonplaceholder.typicode.com/users",
          { timeout: 5000, // Tempo limite de 5000 ms (5 segundos) }
        );
        setUsuarios(response.data);
      } catch (error) {
        if (error.code === "ECONNABORTED") {
          // Erro de timeout
          setTimeoutError(true);
        } else {
          // Outros erros
          console.error("Erro ao carregar usuários:", error);
          setError("Erro ao carregar usuários.");
        }
      } finally {
        setLoading(false); // Atualiza o estado de carregamento para false
      }
 };
 fetchUsuarios();


Observe que:
    - Configuração do Timeout: Ao fazer a requisição com axios.get, um objeto de configuração é passado como segundo argumento, onde timeout: 5000 especifica que a requisição deve falhar se não receber uma resposta em 5 segundos.

    - Tratamento de Erros de Timeout:
        - O bloco catch agora verifica se o erro é um erro de timeout usando if (error.code === 'ECONNABORTED').

        - Se for um erro de timeout, setTimeoutError(true) é chamado para atualizar o estado e exibir uma mensagem específica ao usuário.

        - Para outros tipos de erros, a mensagem de erro genérica é definida como antes.

=-=-= Fallbacks e experiência do usuário =-=-=
Para melhorar ainda mais a experiência do usuário ao lidar com requisições lentas e erros em sua aplicação React, você pode implementar fallbacks e aprimorar a experiência do usuário. Fallbacks podem incluir mensagens ou componentes padrão a serem exibidos quando não há dados disponíveis ou quando ocorrem erros.

Veja um exemplo abaixo:

import { useState, useEffect } from "react";
import axios from "axios";

function App() {
      const [usuarios, setUsuarios] = useState([]);
      const [loading, setLoading] = useState(true); // Estado de carregamento
      const [error, setError] = useState(null);
      const [timeoutError, setTimeoutError] = useState(false); // Estado para erro de timeout
    
    
      useEffect(() => {
        const fetchUsuarios = async () => {
          try {
            const response = await axios.get(
              "https://jsonplaceholder.typicode.com/users",
              {
                timeout: 5000, // Tempo limite de 5000 ms (5 segundos)
              }
            );
            setUsuarios(response.data);
          } catch (error) {
            if (error.code === "ECONNABORTED") {
              // Erro de timeout
              setTimeoutError(true);
            } else {
              // Outros erros
              console.error("Erro ao carregar usuários:", error);
              setError("Erro ao carregar usuários.");
            }
          } finally {
            setLoading(false); // Atualiza o estado de carregamento para false
          }
        };
        fetchUsuarios();
      }, []);
      // Mensagem de carregamento
      if (loading) return <p>Carregando...</p>;
    
    
      // Mensagem de erro de timeout
      if (timeoutError)
        return <p>O carregamento dos usuários demorou demais. Tente novamente.</p>;
      // Mensagem de erro genérico
      if (error) return <p>{error}</p>;
    
    
      // Verifica se não há usuários disponíveis
      if (usuarios.length === 0) return <p>Nenhum usuário encontrado.</p>;
    
    
      return (
        <div>
          <h1>Lista de Usuários</h1>
          <ul>
            {usuarios.map((usuario) => (
              <li key={usuario.id}>{usuario.name}</li>
            ))}
          </ul>
        </div>
      );
}
    
export default App;

Observe neste exemplo:

- Fallbacks para erros:
    - Mensagem de Timeout: Se a requisição ultrapassar o tempo limite, uma mensagem específica é exibida: "O carregamento dos usuários demorou demais. Tente novamente."

    -Mensagem de Erro Genérico: Exibe a mensagem de erro se houver algum problema ao carregar os dados.

    -Fallback para Nenhum Dado: Se a lista de usuários estiver vazia (usuarios.length === 0), uma mensagem "Nenhum usuário encontrado." é exibida. Isso é importante para informar os usuários que não houve dados disponíveis, em vez de deixar a lista vazia.

- Melhoria na Experiência do Usuário:
    - Título da Página: Um título "Lista de Usuários" foi adicionado para contextualizar o que está sendo exibido.

    Organização Visual: Agrupar as mensagens e a lista de usuários em um único contêiner (<div>) melhora a estrutura visual da aplicação.
