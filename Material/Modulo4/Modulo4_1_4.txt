=== Operação com os outros métodos HTTP usando Axios ===
Ao desenvolver aplicações web com React ou outras tecnologias, o uso de métodos HTTP é essencial para realizar operações de manipulação de dados em APIs. Os métodos mais comuns são GET, POST, PUT e DELETE, que permitem buscar, criar, atualizar e excluir dados em um servidor. Vamos explorar em detalhes cada um desses métodos, mostrando exemplos práticos tanto com a Fetch API quanto com o Axios.

=-=-= GET =-=-=
O método GET é utilizado para buscar dados de um servidor. Ele é usado quando precisamos obter informações de uma API sem modificar nenhum dado. As requisições GET são idempotentes, ou seja, podem ser chamadas repetidamente sem alterar o estado do recurso no servidor. Os dados solicitados são passados na URL como parâmetros de consulta (query parameters), se necessário.

Veja abaixo um exemplo de uso do método GET com Fetch API:

function App() {
    // Função assíncrona para fazer a requisição usando o método GET
    const buscarDados = async () => {
      try {
        const response = await fetch(
          "https://jsonplaceholder.typicode.com/posts",
          { method: "GET", }
        );
        if (!response.ok) {
          throw new Error("Erro ao buscar os dados!");
        }
        const data = await response.json();
        console.log("Dados recebidos:", data);
      } catch (error) {
        console.error("Erro na requisição:", error);
      }
    };
    buscarDados();  
    return <h1>GET com Fetch API - Verifique o Console</h1>;
}
export default App;

Observe que:

- A função buscarDados é declarada como assíncrona (async).

- Utiliza a função fetch() para fazer uma requisição GET para o endpoint https://jsonplaceholder.typicode.com/posts, que retorna uma lista de posts.

- O método GET é usado para obter dados de um servidor e é o padrão para a Fetch API, então, tecnicamente, não seria necessário especificá-lo.

- O código verifica se a resposta foi bem-sucedida (status 2xx). Se não, lança um erro com a mensagem "Erro ao buscar os dados!".

- Se a resposta for bem-sucedida, ela é convertida em JSON com response.json(), transformando os dados em um formato que o JavaScript pode manipular.

- Os dados recebidos são exibidos no console do navegador.

Veja abaixo um exemplo de uso do método GET com Axios:

import axios from "axios";
function App() {
  
        // Função assíncrona para fazer a requisição usando Axios com o método GET
        const buscarDados = async () => {
          try {
            const response = await axios.get(
              "https://jsonplaceholder.typicode.com/posts"
            );
            console.log("Dados recebidos:", response.data);
          } catch (error) {
            console.error("Erro na requisição:", error);
          }
        };
      
      
        buscarDados();
        return <h1>GET com Axios - Verifique o Console</h1>;
}
      
export default App;

Observe neste código:

- Axios automaticamente lida com a configuração da requisição e a transformação da resposta em JSON, eliminando a necessidade de verificar manualmente e converter a resposta.

- Com Axios, não precisamos configurar manualmente o método HTTP ou transformar a resposta para JSON usando response.json(), já que Axios faz isso automaticamente.

- Os dados retornados são diretamente acessíveis em response.data.

=-=-= POST =-=-=
O método POST é utilizado para enviar dados para o servidor, geralmente para criar novos recursos. Ele é utilizado quando precisamos submeter informações, como enviar um formulário de cadastro. Diferente do GET, o POST não é idempotente, pois cada requisição pode criar um novo recurso. Os dados são enviados no corpo da requisição, não na URL.

Veja abaixo um exemplo de uso do método POST com Fetch API:

function App() {
    // Função assíncrona para fazer a requisição
    const criarRecurso = async () => {
      try {
        const response = await fetch('https://jsonplaceholder.typicode.com/posts', {
          method: 'POST',
          headers: { 'Content-Type': 'application/json', },
          body: JSON.stringify({
            title: 'Novo Item',
            body: 'Descrição do item',
            userId: 1,
          }),
        });
        if (!response.ok) {
          throw new Error('Erro ao criar recurso!');
        }
        const data = await response.json();
        console.log('Recurso criado:', data);
      } catch (error) {
        console.error('Erro na requisição:', error);
      }
    };
    criarRecurso();
    return <h1>POST com Fetch API</h1>;
}
export default App;

Observe neste código que:

- A função é definida como async, o que permite o uso da palavra-chave await para lidar com operações assíncronas.

- fetch(): Usado para enviar a requisição HTTP do tipo POST para a API.
    - method: 'POST': Especifica que estamos enviando dados para criar um novo recurso no servidor.

    - headers: Define o tipo de conteúdo que estamos enviando, neste caso, application/json, indicando que os dados estão no formato JSON.

- body: Os dados que queremos enviar para o servidor são transformados em uma string JSON usando JSON.stringify(). O objeto enviado contém:
    - title: título do novo item.
    - body: uma descrição do item.
    - userId: identificador do usuário (simulado).

- Verifica se a resposta do servidor foi bem-sucedida. Se não for (response.ok é false), uma exceção é lançada, e uma mensagem de erro é exibida.

- Usa await response.json() para converter a resposta da API em um objeto JavaScript.

- Exibe os dados retornados pelo servidor no console, confirmando que o recurso foi criado.

Agora, veja abaixo um exemplo de uso do método POST com Axios:

mport axios from "axios";

function App() {
  
        // Função assíncrona para fazer a requisição usando Axios
        const criarRecurso = async () => {
          try {
            const response = await axios.post(
              "https://jsonplaceholder.typicode.com/posts",
              {
                title: "Novo Item",
                body: "Descrição do item",
                userId: 1,
              }
            );
            console.log("Recurso criado:", response.data);
          } catch (error) {
            console.error("Erro na requisição:", error);
          }
        };
        criarRecurso();
        return <h1>POST com Axios</h1>;
}
      
export default App;

Faça a seguinte comparação:

- Fetch API: Requer a configuração manual do método, cabeçalhos e conversão dos dados para JSON.

- Axios: Simplesmente aceita os dados diretamente como o segundo argumento, lidando automaticamente com a configuração dos cabeçalhos.

=-=-= PUT =-=-=
O método PUT é usado para atualizar um recurso existente no servidor. Ele substitui completamente o recurso com os dados fornecidos. Assim como GET, PUT é idempotente, o que significa que enviar a mesma requisição várias vezes resulta no mesmo estado. Ele requer que os dados sejam enviados no corpo da requisição. Veja abaixo um exemplo com Fetch API:

function App() {

    // Função assíncrona para fazer a requisição usando o método PUT
    const atualizarRecurso = async () => {
      try {
        const response = await fetch(
          "https://jsonplaceholder.typicode.com/posts/1",
          { // Atualizando o recurso com ID 1
            method: "PUT",
            headers: {"Content-Type": "application/json", },
            body: JSON.stringify({
              title: "Item Atualizado",
              body: "Descrição do item atualizada",
              userId: 1,
            }),
          }
        );
        if (!response.ok) {
          throw new Error("Erro ao atualizar o recurso!");
        }
        const data = await response.json();
        console.log("Recurso atualizado:", data);
      } catch (error) {
        console.error("Erro na requisição:", error);
      }
    };
    atualizarRecurso();
    return <h1>PUT com Fetch API</h1>;
}
export default App;

Observe que:

- A função atualizarRecurso é definida como assíncrona usando async.

- A URL https://jsonplaceholder.typicode.com/posts/1 é usada para indicar o recurso específico que estamos atualizando. O número 1 no final da URL é o ID do recurso que será modificado. 

- method: "PUT": Especifica que a requisição é do tipo PUT, usada para atualizar completamente um recurso existente no servidor.

- O cabeçalho Content-Type: "application/json" indica que o corpo da requisição está sendo enviado no formato JSON.

- O corpo da requisição é convertido em uma string JSON usando JSON.stringify() e contém os dados que queremos atualizar.

- O código verifica se a resposta foi bem-sucedida, utilizando response.ok.

- Após confirmar que a resposta foi bem-sucedida, o código converte os dados retornados pelo servidor em um objeto JavaScript usando response.json().

Veja abaixo um exemplo de uso do método PUT com Axios:

import axios from "axios";
function App() {
        // Função assíncrona para fazer a requisição usando Axios com o método PUT
        const atualizarRecurso = async () => {
          try {
            const response = await axios.put(
              "https://jsonplaceholder.typicode.com/posts/1",
              {
                title: "Item Atualizado",
                body: "Descrição do item atualizada",
                userId: 1,
              }
            );
            console.log("Recurso atualizado:", response.data);
          } catch (error) {
            console.error("Erro na requisição:", error);
          }
        };
        atualizarRecurso();
        return <h1>PUT com Axios</h1>;
}
export default App;

Observe que ambos os métodos funcionam de maneira similar, mas Axios simplifica a configuração e o envio dos dados:

- Com Axios, não precisamos configurar manualmente os cabeçalhos de Content-Type para JSON, pois ele lida automaticamente com a conversão de objetos JavaScript para JSON.

- Usamos axios.put(), passando a URL e o corpo da requisição como argumentos.

- Com Axios, a resposta já vem automaticamente formatada em JSON, então podemos acessar os dados diretamente em response.data, sem precisar usar response.json().

=-=-= DELETE =-=-=
O método DELETE é utilizado para remover um recurso no servidor. O DELETE também é idempotente, o que significa que múltiplas chamadas para o mesmo recurso resultam no mesmo efeito — a remoção do recurso. Normalmente, não requer um corpo na requisição.

Veja abaixo um exemplo de uso do método DELETE com Fetch API:
function App() {

    // Função assíncrona para fazer a requisição usando o método DELETE
    const removerRecurso = async () => {
      try {
        const response = await fetch("https://jsonplaceholder.typicode.com/posts/1", {
          method: "DELETE",
        });
        if (!response.ok) {
          throw new Error("Erro ao remover o recurso!");
        }
        console.log("Recurso removido com sucesso");
      } catch (error) {
        console.error("Erro na requisição:", error);
      }
    };
    removerRecurso();
    return <h1>DELETE com Fetch API</h1>;
}
export default App;
  
Observe que:

- A função removerRecurso é definida como assíncrona utilizando async.

- A URL https://jsonplaceholder.typicode.com/posts/1 especifica o recurso com ID 1 que queremos remover.

- O método DELETE é utilizado para enviar uma requisição ao servidor indicando que o recurso especificado (com ID 1) deve ser excluído.

- A função fetch é usada para enviar a requisição DELETE, e o await faz com que a execução da função seja pausada até que a resposta do servidor seja recebida.

- Se a requisição for bem-sucedida, esta linha imprime uma mensagem no console.

Veja abaixo um exemplo de uso do método DELETE com Axios:

import axios from "axios";
function App() {
        // Função assíncrona para fazer a requisição usando Axios com o método DELETE
        const removerRecurso = async () => {
        try {
        const response = await axios.delete(
        "https://jsonplaceholder.typicode.com/posts/1"
        );
        console.log("Recurso removido com sucesso");
        } catch (error) {
        console.error("Erro ao remover o recurso:", error);
        }
        };
        removerRecurso();
        return <h1>DELETE com Axios</h1>;
}
export default App;

Observe que com Axios, a remoção de recursos é direta e a sintaxe é mais limpa:

- Com Axios, não é necessário configurar manualmente os detalhes da requisição, como o método ou cabeçalhos, já que ele lida automaticamente com essas configurações.

- Com Axios, não precisamos verificar manualmente se response.ok é verdadeiro, pois ele automaticamente lança um erro se a resposta indicar uma falha (códigos de erro HTTP como 4xx ou 5xx). Isso simplifica o tratamento de erros.
